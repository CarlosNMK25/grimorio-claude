    Si no le cuentas que paso antes, empieza de cero.
  • Principio IV
    Pide bien una vez. No pidas mal diez veces.
  • Principio V
    Las herramientas cambian. La filosofia permanece.

Buscar en la red

Invoca conocimiento de internet
▽
nativorequiere conexión
○Aprendiz▽

Piensa en Claude como un asistente que puede buscar información en internet por ti. Es como tener a alguien que sabe usar Google muy bien y te resume lo que encuentra, ahorrándote el trabajo de abrir múltiples páginas.

información general
"Búscame información sobre [tema]"
✓
documentación
"Busca la documentación oficial de [herramienta]"
✓
noticias
"¿Qué novedades hay sobre [tema]?"
✓
◐Mago▽

Claude envía tu consulta a un motor de búsqueda y recibe los 10 resultados más relevantes. Lee títulos, descripciones y URLs, y sintetiza la información.

Limitaciones
  • Solo obtiene los 10 primeros resultados
  • No puede acceder a contenido detrás de login
●Archimago▽

Bajo el capó, Claude usa una herramienta llamada web_search que hace una petición HTTP a un motor de búsqueda. La "magia" es simplemente una llamada a una API que devuelve un JSON con título, URL y fragmento de cada resultado.

comando
web_search
├── query: "tutorial python listas"
└── return: [{ title, url, snippet }]

Leer una página

Extrae el contenido de una URL
▽
nativorequiere conexión
○Aprendiz▽

Es como pedirle a alguien que abra un enlace por ti y te cuente qué dice. Claude puede visitar cualquier página web pública y extraer su contenido para analizarlo o resumirlo.

leer
"Lee esta página: [URL]"
✓
resumir
"Lee y resúmeme: [URL]"
✓
◐Mago▽

Claude accede a la URL, descarga el HTML, lo convierte a markdown limpio y lo procesa. Puede extraer texto, imágenes embebidas y estructura del documento.

Limitaciones
  • No puede acceder a contenido detrás de login
  • JavaScript dinámico puede no cargarse
  • Algunos sitios bloquean bots
●Archimago▽

La herramienta web_fetch hace una petición HTTP GET a la URL indicada, recibe el HTML crudo, lo parsea con un convertidor a markdown y devuelve el texto limpio. Es como wget + html2text combinados.

comando
web_fetch
├── url: "https://..."
└── return: { content, title }

La URL debe incluir https://

Leer archivos

Ver contenido de archivos locales
▽
localMCP Filesystem
○Aprendiz▽

Claude puede abrir y leer archivos que tengas en tu ordenador, igual que si tú los abrieras con un editor de texto. Esto le permite analizar tu código, documentos, o cualquier archivo de texto.

leer
"Lee el archivo [nombre]"
✓
revisar código
"Revisa mi código en [nombre.py]"
✓
◐Mago▽

Claude accede al sistema de archivos a través del servidor MCP. Lee el contenido completo del archivo y lo carga en memoria para análisis.

Limitaciones
  • Solo puede leer archivos en carpetas autorizadas
  • Archivos muy grandes pueden exceder límites de tokens
  • Archivos binarios se muestran codificados
●Archimago▽

El MCP (Model Context Protocol) es un protocolo que permite a Claude comunicarse con tu sistema. El comando read_file envía la ruta al servidor MCP local, que lee los bytes del disco y devuelve el contenido como string.

comando
Filesystem:read_file
├── path: "/ruta/archivo.py"
└── return: "[contenido]"

Crear archivos

Materializa nuevos archivos
▽
localMCP Filesystem
○Aprendiz▽

Claude puede crear archivos nuevos en tu ordenador. Le dices qué quieres que contenga y él lo escribe por ti. Útil para guardar código, crear scripts, o generar documentos.

crear
"Crea un archivo [nombre] que haga [qué]"
✓
guardar
"Guarda ese código en [nombre]"
✓
◐Mago▽

El servidor MCP escribe el contenido especificado en la ruta indicada. Si el archivo existe, lo sobrescribe completamente.

Limitaciones
  • Solo puede escribir en carpetas autorizadas
  • No hay confirmación antes de sobrescribir
  • Permisos del sistema aplican
●Archimago▽

El comando write_file abre un file handle en modo escritura (truncando si existe), escribe los bytes del contenido y cierra el handle. Internamente usa fs.writeFile() de Node.js o equivalente del sistema.

comando
Filesystem:write_file
├── path: "/ruta/nuevo.py"
├── content: "print('hola')"
└── return: "Creado"

Si existe, lo sobrescribe

Editar archivos

Modifica sin borrar todo
▽
localMCP
○Aprendiz▽

En lugar de reescribir un archivo entero, Claude puede hacer cambios puntuales. Es como usar "buscar y reemplazar" en tu editor, pero más inteligente: Claude entiende el contexto del código.

corregir
"En [archivo], corrige [error]"
✓
reemplazar
"Cambia [esto] por [esto otro]"
✓
◐Mago▽

Claude lee el archivo, identifica el texto a reemplazar, genera un diff y aplica los cambios. Es más eficiente que reescribir todo el archivo.

Limitaciones
  • El texto a buscar debe existir exactamente
  • Archivos muy grandes pueden ser lentos
  • Solo texto plano, no binarios
●Archimago▽

El comando edit_file recibe un array de ediciones {oldText, newText}. Internamente busca cada oldText en el archivo y lo reemplaza por newText, generando un diff unificado como verificación.

comando
Filesystem:edit_file
├── path: "/ruta/archivo.py"
├── edits: [{ oldText, newText }]
└── return: "[diff]"

Buscar archivos

Localiza archivos por nombre o contenido
▽
localMCP Filesystem
○Aprendiz▽

¿Tienes muchos archivos y no recuerdas dónde está algo? Claude puede buscar en tu ordenador por nombre de archivo o por texto dentro de los archivos. Es como tener un buscador de Windows/Spotlight potenciado.

por nombre
"Busca archivos que se llamen [nombre]"
✓
por tipo
"Busca todos los [.py] en [carpeta]"
✓
por contenido
"Busca archivos que contengan [texto]"
✓
◐Mago▽

El MCP escanea el directorio recursivamente buscando coincidencias por nombre (glob pattern) o contenido (grep). Devuelve rutas y snippets relevantes.

Limitaciones
  • Solo busca en carpetas autorizadas
  • Búsquedas grandes pueden tardar
  • No indexa, escanea en tiempo real
●Archimago▽

El comando search_files usa glob patterns (como *.py) para buscar por nombre, o expresiones regulares para buscar dentro del contenido. Recorre el árbol de directorios recursivamente con fs.readdir() y aplica los filtros.

comando
Filesystem:search_files
├── path: "/carpeta"
├── pattern: "*.py"
└── return: ["archivo1.py", ...]

Ver estructura

Explora carpetas y subcarpetas
▽
localMCP Filesystem
○Aprendiz▽

Claude puede mostrarte cómo está organizado un proyecto: qué carpetas tiene, qué archivos hay dentro de cada una. Es como ver el árbol de carpetas del explorador de archivos, pero puedes pedirle que te lo explique.

ver
"¿Qué hay en la carpeta [ruta]?"
✓
estructura
"Muéstrame la estructura de [proyecto]"
✓
◐Mago▽

El MCP lista recursivamente archivos y carpetas, generando un árbol jerárquico. Marca directorios y archivos con prefijos [DIR] y [FILE].

Limitaciones
  • Árboles muy profundos pueden ser grandes
  • No muestra archivos ocultos por defecto
  • Permisos pueden bloquear carpetas
●Archimago▽

list_directory devuelve una lista plana de un nivel; directory_tree construye recursivamente un objeto JSON anidado con {name, type, children[]} para representar la jerarquía completa.

comandos
Filesystem:list_directory
├── path: "/carpeta"
└── return: ["[DIR] sub", "[FILE] x.py"]

Filesystem:directory_tree
├── path: "/carpeta"
└── return: { name, type, children }

Ejecutar código

Da vida a tus scripts
▽
localDesktop Commander
○Aprendiz▽

Claude puede ejecutar programas en tu ordenador y decirte qué resultado dan. Es como si tú abrieras la terminal, ejecutaras el script y le contaras a alguien qué pasó. Muy útil para probar código rápidamente.

ejecutar
"Ejecuta el archivo [nombre.py]"
✓
probar
"Ejecuta este código y dime qué sale"
✓
◐Mago▽

Desktop Commander crea un proceso hijo, ejecuta el comando y captura stdout/stderr en tiempo real. Puede mantener sesiones interactivas (REPL) para Python, Node, etc.

Limitaciones
  • Timeout por defecto de 30 segundos
  • Procesos interactivos necesitan interact_with_process
  • No tiene GUI, solo terminal
●Archimago▽

Desktop Commander usa child_process.spawn() para crear un subproceso. Captura stdout/stderr mediante pipes, gestiona el PID para procesos de larga duración, y permite enviar input a procesos interactivos (como un REPL).

comandos
Desktop Commander:start_process
├── command: "python3 script.py"
├── timeout_ms: 30000
└── return: { pid, output }

Desktop Commander:interact_with_process
├── pid: 12345
├── input: "print(2+2)"
└── return: "4"

Claude puede buscar en tus conversaciones anteriores. Si hablasteis de algo hace días o semanas, puede encontrarlo. Es como tener un historial de chat con búsqueda inteligente.

├── semantic_query: "presupuesto Q1"
├── order_by: "modifiedTime desc"
└── return: [{ id, name, snippet }]

Operadores: name contains, fullText contains, modifiedTime >

  • Máximo 100-500 resultados por consulta

●Archimago▽

search_gmail_messages usa la Gmail API con el parámetro q (query) que soporta la misma sintaxis de búsqueda de Gmail. OAuth2 maneja la autenticación; los tokens se renuevan automáticamente.

comandos

├── q: "from:x@email.com is:unread"
└── return: [{ message_id, thread_id, subject, snippet }]

read_gmail_thread

◐Mago▽

Consulta la API de Google Calendar filtrando eventos por rango de fechas, calendario y búsqueda de texto. Devuelve título, fecha, hora y ubicación.

Limitaciones
  • Requiere autorización OAuth
  • Solo calendarios con acceso concedido
  • Zona horaria debe coincidir
●Archimago▽

list_gcal_events hace un GET a la Calendar API v3 con parámetros timeMin/timeMax en formato RFC3339. Filtra por calendar_id (primary = calendario principal) y opcionalmente por query.

comando
list_gcal_events
├── calendar_id: "primary"
├── time_min: "2025-01-17T00:00:00Z"
├── time_max: "2025-01-24T00:00:00Z"
├── query: "reunión"
└── return: [{ summary, start, end }]

○Aprendiz▽

¿Necesitas programar una reunión pero no sabes cuándo tienes tiempo? Claude puede revisar tu calendario (y el de otras personas si tienen acceso) y decirte cuándo todos están libres.

libre
"¿Cuándo tengo tiempo libre esta semana?"
✓

✓
◐Mago▽

Lee todos los eventos en el rango de tiempo especificado, identifica bloques libres entre eventos y sugiere franjas horarias disponibles.

Limitaciones
  • No considera horario laboral automáticamente
  • Puede no detectar eventos "todo el día"
  • Requiere acceso a todos los calendarios implicados
●Archimago▽

find_free_time consulta múltiples calendarios, construye una timeline de eventos ocupados, y calcula los intervalos inversos (tiempo libre). Es un algoritmo de interval merging sobre los busy slots.

comando
find_free_time
├── calendar_ids: ["primary", "otro@email"]
├── time_min: "..."
├── time_max: "..."
└── return: ["Lun 10-12", "Mar 15-17"]

Cuando tienes errores

Entiende y arregla bugs
▽
nativo
○Aprendiz▽

Los errores no son fracasos, son pistas. Cada mensaje de error te está diciendo exactamente qué pasó y dónde. Claude puede traducir esos mensajes crípticos a español llano y ayudarte a arreglarlos.

entender
"Me sale este error: [error]. ¿Qué significa?"
✓
arreglar
"Mi código da error. ¿Puedes revisarlo?"
✓
prevenir
"¿Qué errores típicos se cometen con [tema]?"
✓
◐Mago▽

Cuando copies un error, incluye el mensaje completo. El "traceback" cuenta la historia de qué pasó y en qué línea.

Limitaciones
  • Necesitas copiar el error completo para ayuda efectiva
  • Errores de sintaxis pueden confundir sin contexto
  • Claude no ejecuta código, solo lo analiza
